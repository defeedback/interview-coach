# 技术深挖与模拟面试

## 技术深挖统一模板

对每一个技术点，按以下链条递归追问（一次只问一个）：

```text
技术点
→ 是什么？
→ 为什么使用？
→ 怎么实现？
→ 为什么这样设计？
→ 还有什么方案？
→ 为什么没有选择其他方案？
→ 遇到什么问题？
→ 怎么解决？
→ 怎么验证？
→ 最终效果？
```

### 示例：Hybrid Retrieval 深挖提问链

1. 为什么需要检索？
2. 为什么单纯向量检索不够？
3. 你的关键词检索怎么实现？
4. 向量检索使用什么模型？
5. 向量维度是多少？
6. PostgreSQL 怎么存？
7. 两种检索结果怎么融合？
8. 有没有 Rerank？
9. Rerank 在什么阶段？
10. 怎么判断检索效果？

## 递归追问式模拟面试

扮演面试官，**继续追问直到发现用户的知识边界**。不主动告诉答案。

示例追问链：

```text
Q: 你负责过 RAG 吗？        A: 负责过。
Q: 为什么需要 RAG？         A: 因为企业内部有很多知识。
Q: 为什么不能直接让 LLM 回答？ A: 因为 LLM 不知道企业内部数据。
Q: 那你的 RAG 具体怎么做？   A: 向量检索。
Q: 只有向量检索吗？          A: 还有关键词检索。
Q: 为什么？                 ...
```

**规则**：

- 用户答不上来时，不直接给标准答案 —— 记录为知识漏洞（见 gap-system.md），继续下一个问题或换方向。
- 用户回答含糊时，要求具体化："具体是哪个模型？""参数是多少？""效果怎么衡量的？"
- 一轮模拟结束后，按四类失败类型（Knowledge / Expression / Evidence / Ownership Gap）输出分析。
- 模拟记录写入 `interview/sessions/YYYY-MM-DD-<topic>.md`。

## 面试题树

每个项目自动生成题树，写入 `interview/questions.md`。面试官从任何方向切入，用户都应有对应知识节点：

```text
项目
├── 业务
│   ├── 为什么做？
│   ├── 谁使用？
│   └── 解决什么问题？
├── 职责
│   ├── 你负责什么？
│   ├── 哪些是你写的？
│   └── 团队怎么分工？
├── 架构
│   ├── 整体架构
│   ├── 服务划分
│   └── 数据流
├── RAG
│   ├── 数据
│   ├── Chunk
│   ├── Embedding
│   ├── Retrieval
│   ├── Rerank
│   └── Evaluation
├── LLM
│   ├── Prompt
│   ├── Context
│   ├── Structured Output
│   └── Hallucination
├── 后端
│   ├── FastAPI
│   ├── PostgreSQL
│   └── Redis
├── 部署
│   ├── Docker
│   ├── vLLM
│   └── GPU
└── 问题
    ├── 性能
    ├── 准确率
    ├── 数据
    └── 稳定性
```

按用户实际项目技术栈裁剪题树，不保留与用户项目无关的分支。

## 表达训练的随机化

知识补齐后进行表达训练时，随机变换切入角度，防止背稿：

- 变换起点：从模块开始 / 从问题开始 / 从结果开始
- 变换面试官角色：后端面试官 / AI 应用面试官 / 业务面试官 / HR
- 变换时长：30 秒 / 2 分钟 / 5-10 分钟
- 追问式打断：在用户讲述中随时插入细节追问
